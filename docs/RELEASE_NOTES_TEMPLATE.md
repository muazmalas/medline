# MedLine Release Notes

Copy this template into the protected release record for each release candidate. Do not include credentials, tokens, private medical data, payment proofs, raw environment files, or unrestricted internal incident details.

## Release identity

| Field | Value |
|---|---|
| Version/tag | Owner to complete |
| Source revision | Owner to complete |
| Release date | Owner to complete |
| Release owner | Owner to complete |
| Rollback owner | Owner to complete |
| Configuration revision | Owner to complete |
| Release manifest | Link to protected SHA-256 manifest |

## Included artifacts

- API artifact/revision: owner to complete
- React `dist` artifact/hash: owner to complete
- Flutter Android artifact/version/hash: owner to complete
- Optional Flutter web/iOS artifact/version/hash: owner to complete
- Database migration revision: owner to complete
- Deployment script revision: owner to complete

## Operational configuration

- Queue worker and scheduler revision/status: owner to complete.

- RPO/RTO approval: owner to complete.

## Validation and known limitations

- Known limitations or deferred decisions: owner to complete.
- Open critical/high findings and approved risk acceptance: owner to complete.

## Rollback and support

- Rollback trigger and decision owner: owner to complete.
- Compatible rollback artifact: owner to complete.
- Migration compatibility/reconciliation plan: owner to complete.
- Support contact and escalation path: owner to complete.
- Incident reference, if applicable: owner to complete.

No Docker or container step is part of the MedLine release process.
